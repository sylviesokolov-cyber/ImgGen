# Part 3 — UI

## 3.0 Principles

1. **Progressive disclosure.** Three tiers: *Simple* (prompt + aspect + go), *Advanced* (full generated param panel), *Raw* (JSON editor). Tier is remembered per model. A beginner never sees `allow_fallbacks`; a power user is never more than one tap from it.
2. **The image is the interface.** Dark-first, edge-to-edge, chrome that gets out of the way. Controls dim when a result is on screen.
3. **Cost is always visible.** Never let a tap spend money without the number next to it.
4. **Nothing is ever lost.** Every render, including failures, lands in the library with its full request. No "oops, what was that prompt?"
5. **One-handed.** Bottom sheets and bottom bars; nothing critical in the top corners.

## 3.1 Navigation

Bottom bar: **Generate · Library · Models · Settings**, with a Queue badge that surfaces a bottom sheet when jobs are active.

Adaptive: on tablets/foldables use `NavigationRail` + list-detail (grid left, viewer right). Compose's `ListDetailPaneScaffold` handles this and it's cheap to add early, expensive to retrofit.

## 3.2 Generate (home)

```
┌─────────────────────────────────┐
│ [Nano Banana 2 ▾]      $4.12 ▾ │  model chip · balance
├─────────────────────────────────┤
│                                 │
│      last / in-progress         │  result surface
│           result                │  (shimmer while running)
│                                 │
├─────────────────────────────────┤
│ ╭─────────────────────────────╮ │
│ │ a brass orrery on a walnut  │ │  prompt (expandable)
│ │ desk, raking light…         │ │
│ ╰─────────────────────────────╯ │
│ [16:9] [2K] [🎲 seed] [×4] [⚙] │  quick chips
│ [ref][ref][+]                   │  reference tray
├─────────────────────────────────┤
│    Generate  ·  ~$0.065      ▶ │  cost on the button
└─────────────────────────────────┘
```

- **Model chip** → bottom sheet with pinned models, capability badges, live price.
- **Quick chips** are the 5 params you actually touch. `⚙` opens the full generated panel.
- **Seed chip** has three states: 🎲 random / 🔒 locked / ↻ reuse-last. Long-press to type one.
- **Generate button shows the estimate.** After the call, it's replaced by the *actual* `usage.cost` — users learn real pricing fast.
- **Prompt field** supports the structured builder (§4.1) via a toggle, and inline `{a|b|c}` wildcard highlighting with a live "→ 6 images, ~$0.39" expansion counter.

## 3.3 Param panel (generated)

A bottom sheet rendered from `List<ParamSpec>`, grouped:

- **Geometry** — aspect ratio (visual chips showing the actual shape, incl. ultra-wides), resolution tier, custom W×H when allowed
- **Sampling** — seed, output count, batch count
- **References** — thumbnails with a role selector (Style / Subject / Composition) and weight slider where supported
- **Routing** — provider order, allow-fallbacks, sort by price/latency/throughput
- **Raw** — a syntax-highlighted JSON editor for `passthrough` / `provider.options`, with validation

Unsupported params for the chosen model are **absent, not disabled-and-mysterious.** A "why is X missing?" affordance explains: *"Muse Image doesn't expose seed."*

## 3.4 Viewer

Full-bleed, zoom/pan/double-tap. Swipe between siblings in a batch. Swipe down to dismiss.

Bottom action bar: **Save · Share · Re-roll · Edit · Fork params · Upscale · Delete**
- **Re-roll** — same request, new seed. One tap.
- **Fork params** — loads the request into Generate for editing. The single most-used button in an app like this.
- **Upscale** — re-render at the next resolution tier with the *same seed*, escalating to Pro if the user opted in.

Swipe up on the viewer → **metadata sheet**: prompt, full param list, model, provider actually used, seed, latency, **actual cost**, timestamp. Every field long-press-to-copy.

## 3.5 Canvas (edit)

Modes: **Inpaint · Outpaint · Compose**

- **Inpaint** — brush/eraser mask painting over the image, adjustable brush size, invert, clear, undo stack. Mask exported as the alpha channel or a separate bitmap per what the API expects.
- **Outpaint** — drag the frame outward with ratio presets; the app computes the new canvas and passes the original as a reference.
- **Compose** — the reference tray as a first-class surface: drop 2–5 images, tag each by role, write a composition prompt. This is where Muse Image earns its place.

## 3.6 Library

- Staggered grid, thumbnails only, infinite scroll.
- **Search across everything**: prompt text, model, seed, aspect, cost range, date, provider, favourite, album. Backed by SQL + FTS on prompts — this is why metadata lives in Room and not in file names.
- Multi-select → bulk export / delete / add-to-album / re-roll-all.
- **Compare mode**: select 2–4 → side-by-side or A/B slider with a synced zoom, param diff highlighted beneath. This is how you actually learn which model is better for your work.
- Filter presets: "this week", "failed", "over $0.10", "seed locked".

## 3.7 Models

Browse the live catalog with capability badges (t2i / edit / refs / seed / max refs / resolutions), live pricing, and a latency indicator from your own history. Pin favourites to the model chip. Per-model default preset. A **capability inspector** showing the raw `supported_parameters` — invaluable for debugging and it costs nothing since you already fetch it.

## 3.8 Settings

Auth (Connect via OpenRouter / paste key / sign out) · **Budget** (daily + monthly cap, warn threshold, hard-stop toggle) · Defaults (model, aspect, resolution, disclosure tier) · Storage (location, auto-save, thumbnail cache, clear) · Export/import library · Appearance (AMOLED black, dynamic colour) · About (incl. SynthID / AI-disclosure note).

## 3.9 Visual design

Material 3 Expressive, dynamic colour with a neutral dark fallback, AMOLED-black option. Predictive back. Shared-element transitions grid→viewer (Compose supports this natively now; it makes the app feel finished). Haptics on generate/complete. Motion restrained — the images are the content.

Accessibility is not optional: content descriptions on every image action, 48dp touch targets, `TalkBack` pass on the param panel (generated UI is exactly where a11y silently rots), respect font scaling, and never encode state in colour alone.
